# Lumina 自动化测试架构白皮书 (Automated Testing Strategy)

随着 Lumina V1.8.0 版本的正式落地，代码库体量与交互复杂度已达到商业级阈值。底层涉及 `SQLite` 原子级事务与 `SM-2` 时序引擎，表层涉及 `Electron IPC` 与高定制化视觉组件。

为了打破“依靠人力点按”带来的回归测试瓶颈，避免后续架构重构（如 V2.0 或 Tauri 端迁移）时引发的雪崩效应，特起草本阶段的自动化测试引入方案。

---

## 一、 战略全景：分级部署模型

针对 Electron 系统的特殊性，我们将测试防线切割为三大纵深防区（P0 -> P2），建议按优先级迭代装载。

### 🟢 优先级 P0：核心护城河测试（纯逻辑单元测试 Unit Testing）
> **定位**：保障应用的信任根基。背单词软件的核心资产是算法的精准度与底层数据的绝对安全。

*   **测试靶标**：
    *   **核心算法 (`utils/sm2.js`)**：属于绝对封闭的“无头计算逻辑”。需输入全量边界条件的掌握度参数，断言返回的复习间隔（5分钟、12小时、7天）是否发生毫秒级偏移。
    *   **强落库链路 (`utils/db.js`)**：测试预写式事务的抗压性。例如断言执行删除主词节点后，关联表 `review_logs` 中基于 `ON DELETE CASCADE` 的连带数据是否按预期自动释放。
*   **重火力武装**：建议引入 **`Jest`** 或 **`Vitest`**。
    *   *优势*：具备极致的启动速度和并行计算能力。完美兼容当前 Node.js 的原生 `require` 与文件 I/O，无需开启渲染端即可毫秒级扫荡算法黑盒。

### 🟡 优先级 P1：数据闭环与自动化行为模拟（端到端 E2E Testing）
> **定位**：主线心流的终极保镖。用于代替人类在多窗体（Dashboard / Spotlight / Flashcard）间进行的复杂物理交互验证。

*   **测试靶标**：
    *   **主流程贯通测试**：模拟真实工作流。例如自动拉起浮窗 -> 触发 `Space` 翻面 -> 高频触发键盘 `4321` `keydown` 钩子 -> 断言数据库完成写入且 UI 实现自我销毁。
    *   **离线架构黑盒**：拦截通信路由，强行验证主进程 `get-analytics` 是否精准分发并点亮了 `ECharts` 配置 JSON，而非无脑报错。
*   **重火力武装**：引入目前面向 Electron 最激进的 **`Playwright for Electron`** 拦截器。
    *   *优势*：相比于老派的 Spectron 或 WebdriverIO，Playwright 具有最高级别的 IPC Mock 能力，并可以直接模拟操作系统层级的“幽灵按键”和剪贴板干预。

### ⚪ 优先级 P2：UI 视觉基线测试（组件层 Visual Regression Testing）
> **定位**：强迫症级页面守门员。守护 V1.8.0 花费巨大心血修正的透明边框与毛玻璃渲染。

*   **测试靶标**：
    *   捕捉极客视觉基线。监控主题色变换、`ECharts` 热力图无遮挡渲染状态，以及 `spotlight-container` 周边的去 `box-shadow` 切割平滑度。
    *   一旦检测到新进代码引发了超过 `0.1%` 的像素级差异偏移，CI/CD 管线将在 `npm run dist` 前直接拉闸报警。

## 二、 里程碑与执行建议 (Next Steps)

按照敏捷工程学的原则，首轮覆盖不应铺设过广以防止开发热情遭损噬。

1.  **阶段 1（短期目标）**：将 `Jest` 部署入 `devDependencies`，率先为全量 `SM-2` 与 SQLite CRUD 函数打上铁金刚防弹外衣。
2.  **阶段 2（中期目标）**：搭建 `Playwright` 单例隔离环境。完成基于纯键盘热键操作（`4/3/2/1` 指向）的主交互冒烟测试（Smoke Test）链路闭环。
3.  **阶段 3（长期目标）**：接管至 GitHub Actions，结合跨平台打包系统在代码 Push 阶段实行强制 CI（持续集成）安检。
