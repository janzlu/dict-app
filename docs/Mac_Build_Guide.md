# Mac 版本编译与发布指南 (macOS Build Guide)

由于本项目（英语生词字典）深度集成了基于底层 C/C++ 封装的 SQLite 引擎依赖包 (`better-sqlite3`)，它在构建阶段需要编译专属当前系统架构（如 Windows x64, macOS ARM 芯片等）的原生库链接文件(`.node`)。

因此，**无法直接在 Windows 操作系统上通过交叉计算方式生成苹果 Mac 电脑专属的 `.dmg` / `.app` 安装包。**

为后续顺利分发高规格的 1.5.x 对应 Mac 版本，特将以下两条行业标准化发布流水线记录在此，用于后续推进：

---

## 方案一：硬衔接 —— 实体机转移编译
最简单粗暴、适合个人开发者的路线。该流程必须有一台运行着 macOS 的真实苹果电脑作为终端宿主机。

### 部署步骤：
1. **脱水迁移**：将全套代码转移至 Mac 电脑。**请注意：**一定不要拷贝包含各种 Windows 缓存的 `node_modules` 文件夹和 `dist` 文件夹，只拷贝纯净的源码（涉及 `package.json`、`src`、`docs` 等）。
2. **下载编译基座**：在 Mac 的终端（Terminal）中，以代码根目录为锚点，运行初始化命令：
   ```bash
   npm install
   ```
   > *引擎会自动拦截并感知到此时的宿主是苹果系统（Darwin），开始针对性地下载和编译 M 系列或 Intel 系列专属环境底座。*
3. **执行编译封包**：基础打牢后，直接触发专属发布的魔法指令：
   ```bash
   npm run dist:mac
   ```
4. **提货**：稍等几分钟读条结束之后，您心心念念的纯种 `.dmg` 安装镜像包就在 `dist` 文件夹内诞生了。

---

## 方案二：云原生 DevOps —— GitHub Actions 无人值守构建 (推荐)
极其高大上的专业开源做法。如果你本身只有一台 Windows 也没有多余苹果设备，借助 GitHub 白嫖的巨型企业服务器就是正解方案。

### 部署逻辑：
1. 我们将在项目的根核心脉络内植入一套流水线剧本（`.github/workflows/build.yml`）。
2. 在该剧本中，我们会指挥 GitHub 分配给咱们一台名为 `macos-latest` 的昂贵高算力云端虚拟机，且为这台机器编排一切从 `npm install` 到 `npm run dist:mac` 所有的操作顺序。
3. 它与代码库产生共振绑定——此后你只需要坐在 Windows 前随便敲打几行指令推上去代码版本更新，这台云电脑就会苏醒并全自动走完整套繁琐的编译打包过程。
4. 几分钟后，Mac 固件就直接变成了你的工程的附赠“战利品”（GitHub Release），供所有人直接公开点击下载。
