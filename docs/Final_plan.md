## 🚨 架构师风险警告 & 修正方案

### 1. 致命风险：SQLite 数据库云盘同步损坏
**[原方案隐患]** 建议用户将 SQLite 数据库直接放入 OneDrive/Dropbox 同步。这在技术上是**极度危险**的。云盘客户端不遵循 SQLite 的文件锁机制，尤其在使用 WAL（预写日志）模式时，云盘后台同步极大概率会导致数据库文件产生极度损坏（Corruption）或冲突副本。
**[修正方案：本地为主，JSON 增量同步]** 
SQLite 主库文件必须保存在本地系统目录（如 `%APPDATA%`）。
通过自动将增量数据导出为 JSON 存入 OneDrive，并监听 JSON 文件变化实现「安全云同步」。详情见后续「数据流转与同步架构」。

### 2. 体验缺陷：纯英文 API 不符合本土化学习
**[原方案隐患]** Free Dictionary API 免费但无中文释义，且公用 API 在高频查词时可能面临被限流的问题，这会严重破坏「即时查询」的心流体验。
**[修正方案：双引擎查词方案]** 
引入 **ECDICT** (开源离线英汉词典 SQLite 数据库，由 skywind3000 维护) 配合在线免费 API。
- **首选离线查询**：毫秒级响应，包含音标、中文释义，无需网络。
- **备选在线查询**：离线词库未命中时（如最新热词），使用免费 API 补充。

## 2. 系统进程与 UI 窗口架构

针对「边进阶边工作」，系统不能干扰正常办公。UI 设计必须极致轻量。

```mermaid
graph TD
    Main[主进程 Main Process] --> Tray[系统托盘后台常驻]
    Main --> InputWindow[快速录入/查询浮窗\n(无边框, 置顶)]
    Main --> MainWindow[管理与学习主窗口\n(常规窗口)]
    Main --> FlashcardWindow[随机闪卡迷你浮窗\n(无边框, 置顶, 可穿透点击)]
    
    Tray -.->|快捷键唤醒/点击| InputWindow
    Tray -.->|打开| MainWindow
```

### 界面与交互设计逻辑
1. **主管理界面 (MainWindow)**：用于生词本管理、详细统计查看、设置项调整。
2. **全局聚焦即查 (InputWindow)**：
   - 触发：`Ctrl+Shift+D` 全局响应。
   - 展现：屏幕中央或右下角弹出类似 macOS Spotlight 的极简搜索框。
   - 逻辑：输入英文回车 -> 自动呈现词性/释文 -> 自动入库 -> 再次 `Esc` 消失。**绝不抢夺用户工作视窗的主导权**。
3. **伴写式闪卡 (FlashcardWindow)**：
   - 展现：在屏幕边缘放置一个只有半张名片大小的半透明卡片。
   - 逻辑：按设定的时间间隔（如每 5 分钟）自动轮播今日待复习生词。

## 3. 数据层核心设计

### 3.1 词库状态机 (词汇生命周期)

采用简化版 SM-2 间隔重复算法，减轻学习焦虑。

- **0 - 新录入 (New)**：刚通过快捷键存入，尚未复习。
- **1-3 - 学习中 (Learning)**：还在初始记忆阶段，出现频率较高。
- **4-5 - 掌握 (Mastered)**：进入长期间隔复习阶段。

### 3.2 表结构设计精要

**table: words**
- `id`: PK
- `word`: TEXT UNIQUE (单词原型)
- `translation`: TEXT (中文释义，从 ECDICT 或 API 抓取)
- `phonetic`: TEXT (音标)
- `mastery_level`: INT (熟练度 0-5)
- `next_review_time`: TIMESTAMP (基于间隔复习算法计算)
- `is_sync`: BOOLEAN (是否已同步到云端)
- `updated_at`: TIMESTAMP (用于多端同步冲突解决的最后修改时间)

## 4. 零服务高可用数据同步架构（重构）

> [!IMPORTANT]
> **架构师级无损网盘同步方案 (Local First + Flat File Sync)**

为满足跨设备（如：公司电脑与家里电脑）使用，无需你购买任何服务器，我们将利用你电脑已有的 OneDrive/Dropbox 提供底层支持。

**同步工作流逻辑：**
1. **本地基准**：读写只能在本地的 `%APPDATA%/DictApp/local.db` 中进行，这里支持高并发与应用锁。
2. **设置同步目录**：引导用户在应用设置中选择一个 OneDrive 同步文件夹路径（例如：`D:\OneDrive\DictApp_SyncData\`）。
3. **增量导出（写出）**：每当应用检测到生词本有变更（或应用关闭/退入后台时），主进程会自动将增量变更数据序列化为一个时间戳命名的 `.jsonl` (JSON Lines) 或标准 `.json` 文件放入该 OneDrive 文件夹。
4. **监听合并（读入）**：当应用启动或运行时，监听并扫描该 OneDrive 文件夹内来自**其他电脑**产生的新 JSON 文件。读取后按 `updated_at` 覆盖或合并到本地 SQLite 中。合并完成后可自动归档该同步文件。

这既利用了网盘的穿透性，又100%避免了 SQLite 直接置于同步盘导致的数据库锁死或破损灾难。
